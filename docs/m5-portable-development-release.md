# M5 portable development release inputs

The portable bundle rebuilds the Storage Scan, Clipboard IME and notification
APK helpers from the included Java/smali sources. APKTool 3.0.3, apksig 8.9.1,
the Android `dx` and `zipalign` tools, Android `framework-res.apk`, and the
selected Android 16 system partition are captured as hashed bundle inputs.
Unsigned APK ZIP timestamps are normalized before alignment and signing; the
APK builders record source/tool/key hashes in per-output receipts. Repeated
builds on the same declared toolchain and signing identity produce byte-identical
APK outputs.

The user installer provisions the helper signer under the installation's XDG
state directory with mode 0600. It is never bundled. Existing workspace-local
signers are migrated byte-for-byte before the runtime switches paths, retaining
Android package update compatibility across immutable bundle updates.

The audio compatibility overlay is generated by
`scripts/build_m4_audio_overlays.py` from the packaged `system.raw.img`; its
receipt includes the input image hash, extracted artifact hashes and ELF checks.
The runtime-input closure check verifies that helper builders, build tools,
framework resources, audio recipes and required overlay sources are present.
It reports host interfaces separately because Wayland, PipeWire, Binder, DRM,
rootless namespaces and build utilities are detected on the target host.

This development release consumes a recorded Android diagnostic rootfs and
system image. It does not claim that Android itself is reproducibly built from
AOSP source, nor that the diagnostic image is production-secure. Bundle
integrity, helper rebuildability and Android platform source reproducibility are
separate properties.
