## Chronological recovery

1. The Android 16 x86_64 SDK image (`BE2A.250530.026.D1`) was extracted into the external workspace. Native namespaces, binderfs, staged APEX payloads, a freestanding SELinux compatibility shim and reversible binary overlays made Android init, property service, ServiceManager and Binder work. Zygote forked `system_server`. This shim grants checks without a genuine Android SELinux policy and is development only.
2. Ranchu graphics expected emulator devices and virtio GPU hardware. Native DRM Mapper 5 replaced the ranchu mapper. It supplies stable-C mapper entry points and standard metadata, allowing SurfaceFlinger RenderEngine and EGL hardware-buffer import. Native Allocator v2 creates i915 GEM/PRIME buffers, with a memfd fallback, and carries dimensions, stride, format and size in the native handle.
3. Native Composer3 AIDL v4 replaced only the ranchu composer service through the container overlay. Synchronous hotplug, EDID, display configurations and VSync allowed SurfaceFlinger to publish its Binder services and unblocked DisplayManagerService. The service remains the active graphics transport endpoint.
4. AaaS wire protocol v2 carries DMA-BUF FDs over Unix `SOCK_SEQPACKET` with `SCM_RIGHTS` to the existing M1A.1 Wayland presenter. The host uses Linux DMA-BUF import and KWin's `linux-drm-syncobj-v1` protocol. Earlier black frames were traced beyond transport to Android Vulkan swapchain backing memory.
5. The external SwiftShader patch set adds Android hardware-buffer/Vulkan capability handling, external-fence entry points, deferred `vkBindImageMemory2` handling for `VkNativeBufferANDROID`, internal device-memory allocation and association with `Image::BackingMemory`. At `vkQueueSignalReleaseImageANDROID`, it waits for queue idle and copies image device memory into the AHardwareBuffer with `AHardwareBuffer_lockPlanes` and `unlock`. This CPU copy is essential to the current visible frame. Do not remove it without an integrated regression proof. It does not establish GPU zero-copy rendering.
6. Composer3 had failed AIDL fence deserialization with absent `-1` representations (`UNEXPECTED_NULL`). The later implementation exports already-signaled DRM syncobjs as Linux `sync_file` FDs for present and layer release results. The integer FD type is a sync_file, but the signal is not tied to Wayland completion. Android client-target acquire remains `-1` in live logs.
7. Correcting little-endian RGBA_8888 memory to DRM `ABGR8888` (`0x34324241`) made the host import work. The M1B.7 screenshot showed Android BootAnimation. Historical run `live24` had two committed/presented frames and one release. Later `live26` logs exist. The present handoff reproduced six commits and six presentation feedback events; details are in `results/m1b71/baseline.json`.

## Known correctness boundaries

- The compositor present fence and layer release fences are immediately signaled `sync_file`s. Their AIDL validity does not prove real present or layer-consumer completion. The current Composer3 can return a signaled fence even when `submitFrame()` fails.
- The transport tracks IDs to slots but stores only one release FD per slot. It inserts the ID before send success, and slot reuse can overwrite an earlier release. The reproduced trace submitted slot 1 again before release of its prior ID. No proof of safe Android buffer recycling exists.
- Host `explicit_sync_frames` counts use of the Wayland protocol. When Android passes `acq_fd=-1`, the host signals the acquire point immediately. In this SwiftShader path queue idle and CPU copy are potential synchronous completion evidence, but SurfaceFlinger client-target composition and its acquire-fence contract still need a call-path audit.
- The host may stage a memfd into a GBM buffer using a second CPU copy. It also writes diagnostic PPMs to fixed repo paths. Direct DMA-BUF imports avoid that stage, but the SwiftShader copy still exists.
- `Image::prepareForExternalUseANDROID` copies `imageRowBytes` per row without proving the destination row is that large and ignores missing source memory and `AHardwareBuffer_unlock` failure. `vkBindImageMemory2` does not propagate an allocation failure. These require targeted fixes and tests.
- Presentation feedback is visibility feedback, not release. `wl_buffer.release`, release timeline completion, transport release, and Android ownership return are separate events. Shutdown currently leaves the last imported frame without a release message in the six-frame baseline.
- The runtime is diagnostic: staged APEX and SELinux compatibility code do not meet Android production isolation guarantees. Do not run untrusted APKs or expose the Binder/socket endpoints to other host users.

Preserve Android 16, the namespace runtime, Mapper 5, Allocator v2, Composer3, the external SwiftShader patches, wire v2 and the host presenter. Earlier AOSP rebuild, replacement-image and graphics-stack approaches did not produce this result and should not be reintroduced casually.
